The first version of this memo (pushed ~10:00) was wrong in a way that matters. An independent
review caught it, I verified every claim against the code, and the reviewer was right on all
four technical points:

1. **I bypassed `consolidate.py`.** The skill's Phase 3 says `consolidate.py` writes the `bucket`
   column; I hand-wrote `scores.csv` with an ad-hoc script instead. My file had no `bucket`,
   `veto`, `thin`, or `theme_rank` columns — so the "buy" list in the first memo was my prose
   opinion, not the rule's output.
2. **The rule's actual buys are URNM and UFO — not eight funds.** The buy rule (README §2) is
   `cause ≥ 7 and (stabilizing or catalyst ≥ 7) and not thin and theme_rank == 1`. Six of my
   eight "buys" (IGF, XLU, SLV, XAR, GLD, BOTZ) fail the gate: none are stabilizing and none
   have catalyst ≥ 7. My "Deviations" section never mentioned this — the biggest deviation of
   all. The README allows overriding a bucket, but every deviation needs one sentence; I
   declared the small ones and skipped the six that mattered.
3. **I also skipped the `thin` penalty.** R/R < 1.3 costs 1 point of weighted score. The rule
   demotes GRID (7.70 → 6.70), ARKQ, ROBO, BAI, QTUM. My table didn't.
4. **The ballot files were in the wrong format.** `consolidate.py` parses numbered-row ballots
   (`| 1 | URNM | 10 | note |`); I told the panelists to write a different column layout, so
   the script couldn't have read them anyway. Fixed: ballots rewritten in parser format,
   `scores.csv` below is 100% `consolidate.py` output.
